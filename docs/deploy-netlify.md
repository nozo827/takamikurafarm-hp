# Netlify で確認用サイトを公開する手順

新しいホームページを、クライアントに見てもらうための **確認用 URL**（例:
`https://takamikurafarm-preview.netlify.app`）として公開するための手順です。

対象: このリポジトリを一緒に開発しているメンバー
所要時間: 15〜20 分（アカウント登録を含む）

---

## 0. はじめに読んでください

### この作業で起きること・起きないこと

| | |
|---|---|
| ✅ 起きること | `*.netlify.app` という仮の URL で新サイトが見られるようになる |
| ❌ 起きないこと | **現在公開中の takamikurafarm.com は一切変化しません** |

現行サイトはロリポップ！というレンタルサーバーで動いていて、今回触る Netlify とは
まったく別の場所です。ドメイン（takamikurafarm.com）の向き先を変えない限り、
本番サイトには影響しません。この手順にドメインを変更する操作は含まれていないので、
**安心して進めて大丈夫です**。失敗してもサイトが落ちることはありません。

### 前提知識

このプロジェクトは **Astro** という仕組みで作られています。ざっくり言うと、

```
リポジトリのソースコード  →（ビルド）→  ただの HTML/CSS/画像  →  Netlify に置く
```

という流れです。「ビルド」は、部品に分けて書いたコードを、ブラウザが読める
HTML に組み立て直す作業のこと。Netlify はこれを**自動でやってくれる**ので、
私たちは GitHub に push するだけで済みます。

### 事前に必要なもの

- GitHub アカウント（`nozo827/takamikurafarm-hp` を読める権限があること）
- メールアドレス

> **確認**: Netlify のアカウントは、**長く管理を続ける人のもので作ってください**。
> サイトは「作った人のアカウント」に紐づきます。学習目的の個人アカウントで作ると、
> あとで引き継ぎが面倒になります。判断に迷ったら作業前に相談してください。

## 1. Netlify に登録する

1. https://www.netlify.com/ を開く
2. 右上の **「Sign up」** をクリック
3. **「Sign up with GitHub」** を選ぶ
   - GitHub アカウントで登録すると、あとでリポジトリを接続する手順が省けます。
     メールアドレスで登録すると、後から GitHub 連携をやり直すことになるので、
     必ず GitHub を選んでください
4. GitHub の認可画面が出たら **「Authorize Netlify」** を押す
5. 登録直後にアンケートやプラン選択が出たら、**無料プラン（Starter / Free）**を選ぶ
   - このサイトの規模なら無料枠で十分足ります。クレジットカードの登録は不要です

---

## 2. リポジトリを Netlify に接続する

1. Netlify の管理画面で **「Add new site」** → **「Import an existing project」** を選ぶ
2. **「Deploy with GitHub」** をクリック
3. GitHub の権限選択画面が出る
   - `takamikurafarm-hp` だけを選んで許可すれば十分です（全リポジトリを許可する
     必要はありません）
   - リポジトリが一覧に出てこない場合は、画面下の
     **「Configure the Netlify app on GitHub」** から、対象リポジトリを追加してください
4. 一覧から **`nozo827/takamikurafarm-hp`** を選ぶ

---

## 3. ビルド設定を確認する

設定画面が出ます。リポジトリに `netlify.toml` という設定ファイルを置いてあるので、
**基本的に何も入力せずそのまま進めて構いません**。念のため、以下になっているか
目視で確認してください。

| 項目 | あるべき値 | 意味 |
|---|---|---|
| Branch to deploy | `master` | このブランチの内容が公開される |
| Build command | `npm run build` | ソースコードを HTML に組み立てるコマンド |
| Publish directory | `dist` | 組み立て結果が出力される場所。ここが公開される |

確認したら **「Deploy takamikurafarm-hp」**（または「Deploy site」）を押します。

---

## 4. デプロイの完了を待つ

1〜2 分でビルドが終わります。画面のログが流れるので眺めていてください。

**成功したとき**、ログの最後のあたりにこう出ます。

```
4 page(s) built in ...
Site is live ✨
```

画面上部に `https://ランダムな名前.netlify.app` という URL が表示されます。
これが確認用サイトの URL です。クリックして開いてみてください。

**失敗したとき**（`Failed` と赤く出る）は、この文書の最後
「うまくいかないとき」を見てください。

---

## 5. URL を分かりやすい名前に変える

初期状態の URL は `graceful-pudding-a1b2c3.netlify.app` のような自動生成の名前です。
クライアントに送るには分かりにくいので、変更します。

1. 左メニューの **「Site configuration」** → **「General」** → **「Site details」**
2. **「Change site name」** をクリック
3. `takamikurafarm-preview` などと入力して保存
   - 世界中で重複しない名前である必要があるため、埋まっていたら
     `takamikurafarm-hp-preview` など少し変えてください

URL が `https://takamikurafarm-preview.netlify.app` になります。

---

## 6. 動作確認

クライアントに渡す前に、以下をひと通り見てください。**スマートフォンでも必ず確認**
してください（見に来る人の多くはスマホです）。

- [ ] トップページが表示される
- [ ] ヘッダーのメニューから各セクションに移動できる
- [ ] 「お知らせ」の一覧ページ（`/news`）が開く
- [ ] お知らせの個別ページが開く
- [ ] 「お問い合わせ」ページ（`/contact`）が開く
- [ ] 写真がすべて表示されている（読み込めていない箇所がないか）
- [ ] スマホで見たときにレイアウトが崩れていない
- [ ] 文字化けしていない

> **お問い合わせフォームは Netlify Forms で受け取ります。**
> 外部サービスの契約は不要で、送信内容は Netlify の管理画面に保存されます。
> ただし**メール通知は初期状態ではオフ**です。次の「7. お問い合わせフォームの
> 通知先を設定する」を必ず行ってください。設定するまでは、送信があっても
> メールは届きません（管理画面には残ります）。
> テスト送信するときは、本文に「テスト送信です」と書いてください。

---

## 7. お問い合わせフォームの通知先を設定する

お問い合わせフォームは **Netlify Forms** という Netlify 標準の機能で受け取ります。
送信された内容は Netlify の管理画面に保存されますが、**メール通知は初期状態では
オフ**なので、ここで通知先を登録します。

### 7-1. フォームが検出されているか確認する

Netlify はデプロイのたびに HTML を解析して、フォームを自動で見つけます。

1. サイトの画面上部にある **「Forms」** タブを開く
2. 一覧に **`contact`** があれば検出できています

`contact` という名前は `src/pages/contact.astro` の `name="contact"` から来ています。

一覧が空の場合は、**「Site configuration」→「Forms」→「Form detection」** が
Enabled になっているか確認したうえで、**「Deploys」** タブから
**「Trigger deploy」** でデプロイし直してください。フォームは*デプロイのとき*に
検出されるため、設定を有効にしただけでは一覧に出てきません。

### 7-2. 通知先メールを登録する

1. 左メニューの **「Site configuration」** を開く
2. **「Notifications」** → **「Emails and webhooks」**
3. **「Form submission notifications」** の欄で
   **「Add notification」** → **「Email notification」** を選ぶ
4. 次のように入力する

   | 項目 | 入れる値 |
   |---|---|
   | Event to listen for | `New form submission` |
   | Form | `contact` |
   | Email to notify | 通知を受け取りたいアドレス（例: `info@takamikurafarm.com`） |

5. **「Save」** を押す

**「Forms」タブ → 対象フォーム → 「Settings and usage」→「Form notifications」**
からも同じ設定画面に入れます。どちらから設定しても結果は同じです。

### 7-3. 設定するときの注意

- **複数の宛先に送りたいときは、通知を宛先の数だけ追加してください。**
  1 つの欄にカンマ区切りで並べる形式ではありません。
- **通知メールの送信元は Netlify のアドレス**（`no-reply@netlify.com` など）です。
  迷惑メールに振り分けられやすいので、最初のテスト送信のあとに迷惑メールフォルダを
  確認し、受信許可リストに入れておいてください。
- **お問い合わせの原本は「Forms」タブに残ります。** メールが届かなかった場合でも、
  ここを見れば内容を確認できます。
- 無料プランで受け取れるのは **月 100 件まで**です。この規模のサイトなら通常は
  問題になりません。

### 7-4. テスト送信して確認する

1. 公開された `/contact` ページを開いてフォームを送信する
   - 本文に「テスト送信です」と書いておいてください
2. 送信後に「お問い合わせありがとうございます」のページ（`/contact/thanks`）が
   表示されれば、送信は成功しています
3. Netlify の **「Forms」** タブに送信内容が並んでいることを確認する
4. 7-2 で登録したアドレスに通知メールが届いていることを確認する（迷惑メールも見る）

---

## 8. クライアントへの共有

URL をそのまま伝えれば見てもらえます。パスワードはかかりません。

このサイトは **takamikurafarm.com の本番サイトとして公開する**ものです。
以前あった検索避け（`X-Robots-Tag: noindex`）は、本番で検索結果から消えてしまうため
削除しました。**`netlify.toml` に noindex を再追加しないでください。**

## 9. これ以降の更新のしかた

**一度つないでしまえば、あとは何もしなくて大丈夫です。**

`master` ブランチに push すると、Netlify が自動でビルドし直して、確認用サイトも
自動で新しくなります（1〜2 分後）。管理画面での操作は不要です。

また、**プルリクエストを作ると、そのブランチ専用のプレビュー URL** が自動で作られ、
PR のコメント欄に貼られます。「この変更を入れる前に見比べたい」というときに便利です。

## うまくいかないとき

### ビルドが `Failed` になる

1. Netlify の **「Deploys」** タブから、失敗したデプロイをクリック
2. ログの中の赤い `Error` の行を探す
3. その部分をコピーして共有してください

よくある原因:

| ログに出る内容 | 原因と対処 |
|---|---|
| `npm ci can only install...` | package-lock.json のズレ。ローカルで `npm install` して結果を commit |
| `Cannot find module ...` | 必要なパッケージが package.json に入っていない |
| `The engine "node" is incompatible` | Node のバージョン。`netlify.toml` の `NODE_VERSION` を確認 |

### サイトは表示されるが、写真が出ない・レイアウトが崩れる

ブラウザのキャッシュが原因のことがあります。スーパーリロード
（Mac: `Command + Shift + R`）を試してください。それでも直らなければ、
どのページのどこが崩れているかスクリーンショットを添えて共有してください。

### お問い合わせフォームを送信しても通知メールが届かない

上から順に確認してください。

1. Netlify の **「Forms」** タブに送信内容が入っているか
   - **入っている** → 通知設定の問題です。「7-2」をやり直し、宛先アドレスに
     打ち間違いがないか確認してください。迷惑メールフォルダも見てください
   - **入っていない** → フォームが検出されていません。「7-1」を確認してください
2. ビルド結果の `dist/contact/index.html` に、`name="contact"` の `<form>` と
   `<input type="hidden" name="form-name" value="contact">` の両方があるか
   - どちらかが欠けていると、Netlify はフォームとして扱いません

### リポジトリが Netlify の一覧に出てこない

GitHub 側でリポジトリへのアクセス権がない可能性があります。リポジトリの所有者に
コラボレーターとして招待してもらってください。

## 付録: 手元のパソコンで開発サーバーを動かす

コードを編集しながら確認したいときの手順です。デプロイだけなら不要です。

```sh
# 1. Node.js を入れる（未導入の場合。Mac + Homebrew の場合）
brew install node

# 2. リポジトリの中で、必要なパッケージをダウンロードする
npm install

# 3. 開発サーバーを起動する
npm run dev
```

`http://localhost:4321` をブラウザで開くと表示されます。
ファイルを保存すると自動で画面に反映されます。止めるときは `Control + C`。

主なファイルの場所:

| 変えたいもの | 場所 |
|---|---|
| 文言・商品情報・連絡先など | `src/data/site.ts` |
| トップページの各セクション | `src/components/sections/` |
| ページそのもの | `src/pages/` |
| 写真 | `src/assets/photos/` |
